# Data Model Specification

**Purpose:** Logical **entities**, **relationships**, **update frequency**, **storage**, and **retention** for Production Memory — Postgres + Inngest only in Hybrid V1.

---

## Entity relationship (logical)

```mermaid
erDiagram
  ORGANIZATION ||--o{ PROJECT : owns
  PROJECT ||--o{ PROTECTION_EVENT : append
  PROJECT ||--o{ PROTECTION_SNAPSHOT : daily
  PROJECT ||--o{ PROTECTION_RECOMMENDATION : has
  PROJECT ||--o{ PROTECTION_DEPLOYMENT : logs
  PROJECT ||--o| PROJECT_MEMORY_PROFILE : one
  PROJECT ||--o{ PROTECTION_MILESTONE : derives
  PROTECTION_SNAPSHOT ||--o{ SNAPSHOT_METRICS : embeds
  PROTECTION_RECOMMENDATION ||--o{ PROTECTION_EVENT : generates
  VERDICT ||--o{ PROTECTION_EVENT : generates
  SCAN_JOB ||--o{ PROTECTION_EVENT : generates
```

### `project_memory_profile` (derived, Hybrid V1 ship)

**One row per project** — updated on review + weekly job. Not a second event log.

| Attribute | Purpose |
|-----------|---------|
| stack_fingerprint | Inferred: Next.js, Stripe, Supabase, etc. (labels only) |
| first_protected_at | First successful review |
| continuous_protection_days | Running count while CP ON (resets on pause) |
| total_daily_checks | Counter |
| total_unsafe_prevented | Counter deploy_blocked |
| total_critical_fixed | Counter fix_verified critical |
| lifetime_production_confidence_delta | First snapshot → latest |
| lifetime_security_confidence_delta | Same |
| last_material_change_at | nullable |

**Smarter over time (V1):** Better **ranking** of worries using recurrence counts in payload — not ML.

## Relationships summary

| From | To | Cardinality |
|------|-----|-------------|
| Project | Events | 1:N append |
| Project | Snapshots | 1:N one per day max |
| Project | Profile | 1:1 |
| Project | Milestones | 1:N sparse |
| Recommendation | Events | 1:N via types safe_fix, fix_verified |
| Snapshot | Previous snapshot | N:1 diff for what_changed |

## Storage strategy

| Tier | Store | Access |
|------|-------|--------|
| Hot | Postgres all tables | MCP + UI |
| Warm | Same | Reports job reads SQL |
| Cold (&gt;12mo) | Object archive **backlog** | Export only |

**No** full code, lockfiles, or chat in Postgres jsonb.

**Indexes:** See [14-future-architecture-scaling.md](./14-future-architecture-scaling.md).

---

## Retention strategy

| Data | Hybrid V1 retention |
|------|---------------------|
| protection_events | 12 months minimum hot |
| protection_snapshots | 12 months minimum |
| recommendations | Life of project |
| deployments | 12 months |
| milestones | Life of project |
| profile | Life of project |
| weekly/monthly cache | 12 months |

Tenant delete: cascade project memory (GDPR) — documented ops runbook backlog.

---

## Tenancy & RLS

All entities scoped by `organization_id` via project join. Service role writes from Inngest; user reads via member JWT.

---

## Acceptance criteria

- ER diagram implemented as logical separation even if tables merged in MVP.  
- Snapshot upsert idempotent per (project, date).  
- Profile counters match event aggregates in golden tests.
